## 1. 프로젝트 개요

본 프로젝트는 4개 사이트(A~D)와 백본 구간(E, F, G)으로 구성된 엔터프라이즈 네트워크를 설계 및 구축하는 것을 목표로 한다. 각 라우터(R1~R4)는 OSPF 기반의 백본으로 연결되며, 각 사이트는 VLAN으로 분리된 내부 네트워크를 가진다.

과제 요구사항인 VLSM 서브네팅과 이중 링크 기반 라우팅에 더해, 아래 항목을 추가로 설계·구현하여 완성도를 높였다.

- VLAN 분리 및 Router-on-a-Stick / SVI 혼합 구성 (사이트별 상이한 inter-VLAN 라우팅 방식 적용)
- OSPF 멀티에어리어(Area 0~4) 구조 설계
- 이중 링크에 대한 OSPF Cost 기반 주(Primary)/부(Backup) 경로 설계 및 장애 우회 테스트
- ACL을 통한 VLAN 간 접근 제어(관리자 자원 보호)
- 정적 라우팅과 동적 라우팅을 결합한 분할 라우팅(디폴트 라우트) 구성

![](img/fig01.png)

- Wireshark(Packet Tracer Simulation Mode)를 통한 MAC 주소 갱신, VLAN 태깅, ACL 차단, OSPF Hello 패킷 분석

### 1.1 개발 및 실습 환경

본 프로젝트는 Cisco Packet Tracer 시뮬레이터 환경에서 설계 및 구현되었다. 실제 사용된 장비 모델 및 소프트웨어 환경은 아래와 같다.

| 구분 | 사용 환경 |
|---|---|
| 시뮬레이션 툴 | Cisco Packet Tracer |
| 라우터 | Cisco 2811 (기본 인터페이스 부족 구간은 NM-4E 이더넷 확장 모듈 추가) |
| 스위치 (L2) | Cisco Catalyst 2960-24TT (사이트 A, B) |
| 스위치 (L3) | Cisco Catalyst 3560-24PS (사이트 C, D) |
| 라우팅 프로토콜 | OSPFv2 (Dynamic Routing) + 정적 라우팅(분할 라우팅 구간) |
| 분석 도구 | Packet Tracer Simulation Mode (Wireshark 대체 캡처 기능) |

Packet Tracer는 실제 IOS 장비와 일부 동작 차이가 있으며(예: 특정 확장 모듈의 인식 방식, CLI 문법 제약 등), 이로 인해 발생한 문제와 대응 과정은 5절 트러블슈팅에 상세히 기술하였다.

### 1.2 OSPF 멀티에어리어 구조 설계의 이점

백본(Backbone)은 여러 사이트(지사) 네트워크를 하나로 연결하는 중심 경로를 의미하며, 본 프로젝트에서는 R1–R2–R3–R4 간 이중 링크 구간(E, F, G)이 이에 해당한다. 각 사이트는 이 백본을 통해서만 다른 사이트와 통신할 수 있는 계층적 구조를 가진다.

OSPF에서 Area는 라우터 간 상세 정보(LSA) 교환 범위를 제한하는 논리적 구역이다. OSPF 규약상 반드시 하나의 'Area 0'이 존재해야 하며, 이는 다른 모든 Area가 상호 통신하기 위해 반드시 거쳐야 하는 백본 역할을 수행한다. 본 프로젝트에서는 개념적으로 사용해온 '백본'을 실제 OSPF의 Area 0으로 정확히 대응시키고, 각 사이트를 Area 1~4로 분리하는 멀티에어리어 구조를 설계하였다.

| Area | 구성 요소 |
|---|---|
| Area 0 (백본) | R1↔R2(E), R2↔R3(F), R3↔R4(G) 이중 링크 전체 |
| Area 1 ~ 4 | 각 사이트(A~D)의 라우터 및 내부 네트워크 |

멀티에어리어 설계는 다음과 같은 실질적 이점을 가진다.

- LSA 전파 범위 축소: 특정 Area 내부의 변화(링크 장애 등)는 해당 Area 안에서만 상세히 전파되고, 타 Area에는 요약된 경로 정보만 전달되어 불필요한 SPF 재계산 부하를 줄인다.
- 장애 영향 범위 제한(Fault Isolation): 한 사이트 내부의 문제가 백본 전체 또는 다른 사이트의 라우팅 안정성에 영향을 주지 않는다.
- 계층적 설계 원칙의 실제 구현: '백본'이라는 설계 개념을 실제 프로토콜 요소(Area 0, ABR)와 일치시켜 이론과 구현을 연결하였다.
- ABR(Area Border Router) 구조 확인: R1~R4는 각각 자신의 사이트 Area와 Area 0을 동시에 연결하는 ABR 역할을 수행하며, 이는 `show ip route`에서 타 Area 경로가 'O IA(OSPF Inter-Area)'로 표시되는 것을 통해 실제로 검증하였다.

### 2.2 전체 토폴로지 및 OSPF Area 구성

백본(R1~R4 간 이중 링크)을 Area 0으로 설정하고, 각 사이트를 별도의 Area로 분리하여 장애 영향 범위를 최소화하는 계층적 설계를 적용하였다. 각 라우터는 자신이 속한 사이트 Area와 Area 0을 동시에 연결하는 ABR(Area Border Router) 역할을 수행한다.

| Area | 구성 요소 |
|---|---|
| Area 0 (백본) | R1↔R2(E), R2↔R3(F), R3↔R4(G) 이중 링크 전체 + R2↔R5 링크 |
| Area 1 | R1 + 사이트 A (SW0, VLAN10/20, PC0-0~2) |
| Area 2 | R2 + 사이트 B (SW1, VLAN10/20, PC1-0~2) |
| Area 3 | R3 + 사이트 C (SW2, VLAN10/20, PC2-0~2, SVI 업링크) |
| Area 4 | R4 + 사이트 D (SW3, VLAN10/20, PC3-0~2, SVI 업링크) |

이중 링크(E, F, G)는 각 구간마다 서로 다른 서브넷을 갖는 두 개의 물리 링크로 구성되며, 하나를 주 경로(Primary, OSPF Cost 10), 다른 하나를 부 경로(Backup, OSPF Cost 100)로 설정하여 평상시에는 주 경로만 사용하고 장애 발생 시 자동으로 부 경로로 우회하도록 설계하였다.

## 3. 구현 내용

### 3.1 장비 선택 및 구성 근거

본 프로젝트의 백본 구조(R1–R2–R3–R4 이중 링크)상, 체인 중간에 위치한 R2·R3는 사이트 연결(1개) + 양방향 이중 링크(4개) = 총 5개의 인터페이스가 필요하다. 반면 체인 끝에 위치한 R1·R4는 3개로 충분하다. 이에 따라 아래 기준으로 라우터 및 스위치 모델을 선정하였다.

| 장비 | 선정 모델 | 선정 근거 |
|---|---|---|
| 라우터 (R1, R4) | Cisco 2811 (기본 포트) | 필요 인터페이스 3개로 기본 온보드 포트만으로 충족 |
| 라우터 (R2, R3) | Cisco 2811 + NM-4E | 필요 인터페이스 5개 → 확장 모듈 필요. NM-4E는 순수 라우팅 전용 이더넷 모듈로, 스위칭 전용 모듈(HWIC-4ESW 등)과 달리 인터페이스에 직접 IP 할당이 가능함 |
| 스위치 (SW0, SW1) | Catalyst 2960 (L2) | Router-on-a-Stick 구성이므로 라우팅 기능 불필요, L2 스위칭만으로 충분 |
| 스위치 (SW2, SW3) | Catalyst 3560 (L3) | SVI 구성을 위해 `ip routing` 및 VLAN 인터페이스 생성 기능이 필요하여 L3 스위치로 선정 |

특히 확장 모듈 선정 시, 모듈 내부에 스위칭 ASIC이 내장된 모듈(HWIC-4ESW, NIM-ES2-4 등)은 하드웨어적으로 라우팅 인터페이스를 지원하지 않으므로 사전에 배제하는 것이 중요하며, 이 판단 기준은 5절 트러블슈팅 1번 항목에서 실제 발생 사례를 통해 검증하였다.

### 3.2 Router-on-a-Stick vs SVI — 혼합 구성

동일 프로젝트 내에서 두 가지 Inter-VLAN Routing 방식을 사이트별로 다르게 적용하여, 두 방식의 구조적 차이를 직접 비교할 수 있도록 설계하였다.

| 사이트 | 라우터 | 스위치 | Inter-VLAN 방식 |
|---|---|---|---|
| A | R1 (2811) | SW0 (2960, L2) | Router-on-a-Stick |
| B | R2 (2811) | SW1 (2960, L2) | Router-on-a-Stick |
| C | R3 (2811) | SW2 (3560, L3) | SVI |
| D | R4 (2811) | SW3 (3560, L3) | SVI |

Router-on-a-Stick 구조에서는 스위치가 트렁크(802.1Q)로 프레임을 전달하고 라우터의 서브인터페이스(예: Ethernet1/3.10, Ethernet1/3.20)가 VLAN별 게이트웨이 역할을 수행한다. SVI 구조에서는 L3 스위치 내부에 VLAN 인터페이스(SVI)를 직접 생성하여 스위치 자체가 라우팅을 수행하며, 라우터와의 연결은 트렁크가 아닌 Routed Port(무IP 스위칭 포트가 아닌 순수 라우팅 링크)로 구성된다.

이 구조적 차이로 인해 SVI 방식은 PC → 게이트웨이 구간에서 별도의 트렁크 홉 없이 스위치 내부에서 즉시 라우팅되는 반면, Router-on-a-Stick 방식은 PC → 스위치(트렁크) → 라우터의 추가 홉을 거친다는 점을Packettracer의 캡처를 통해 확인하였다(4.4절 참조).

| 비교 항목 | Router-on-a-Stick | SVI |
|---|---|---|
| VLAN 라우팅 처리 위치 | 라우터(소프트웨어 기반) | L3 스위치 내부(하드웨어 ASIC) |
| PC → 게이트웨이 경로 | 스위치(트렁크) → 라우터, 홉 1개 추가 | 스위치 내부에서 즉시 처리 |
| VLAN 증가 시 확장성 | 트렁크 링크 하나에 부하 집중 | 병목 없이 확장 용이 |
| 장비 비용/구성 | L2 스위치 + 라우터로 저비용 구성 가능 | L3 스위치 필요, 상대적 고비용 |

### 3.3 VLAN 및 게이트웨이 설계

각 사이트마다 VLAN10(일반 사용자)과 VLAN20(관리자) 2개를 구성하고, PC 3대를 VLAN10에 2대, VLAN20에 1대로 배치하여 서로 다른 VLAN 간 통신 시 반드시 게이트웨이(라우터/SVI)를 경유하도록 하였다.

#### 4.4.1 MAC 주소 및 IP 주소의 홉 간 변화

PC0-0(172.16.0.2, 사이트 A) → PC2-0(172.16.24.2, 사이트 C) 통신을 캡처하여, 매 홉(R1, R2)을 지날 때마다 MAC 주소는 갱신되고 IP 주소는 종단 간(End-to-End) 유지됨을 확인하였다.

| 구간 | Source MAC | Destination MAC | Source IP | Destination IP | TTL |
|---|---|---|---|---|---|
| PC0-0 → R1 | 0001.97ED.0525 | 0060.2F88.C4C7 | 172.16.0.2 | 172.16.24.2 | 255 |
| R1 → R2 | 000B.BE6C.CE31 | 0006.2A82.3C02 | 172.16.0.2 | 172.16.24.2 | 254 |
| R2 → R3 | 0006.2A82.3C01 | 0010.114C.C842 | 172.16.0.2 | 172.16.24.2 | 253 |

MAC 주소는 라우터가 프레임을 수신할 때 디캡슐화하고, 라우팅 결정 후 다음 홉에 맞는 새로운 L2 헤더로 재캡슐화하기 때문에 매 홉마다 변경된다. 반면 IP 주소는 출발지-목적지 종단 간 정보를 담고 있어 전 구간에서 변하지 않는다. 또한 TTL 값이 홉마다 1씩 감소(255→254→253)하는 것을 통해 패킷이 거친 라우터의 수를 정량적으로 확인할 수 있었다.

#### 4.4.2 VLAN 태깅(802.1Q) 확인

PC0-0(VLAN10) → PC0-2(VLAN20) 통신(동일 사이트 내 타 VLAN)을 캡처하여, 액세스 포트 구간과 트렁크 포트 구간의 프레임 형식 차이를 확인하였다.

| 구간 | 프레임 형식 | TPID | TCI (VLAN) |
|---|---|---|---|
| PC0-0 → Sw0 (액세스) | Ethernet II | - | 태그 없음 |
| Sw0 → R1 (트렁크) | Ethernet 802.1q | 0x8100 | 0x00a (VLAN 10) |

트렁크 구간에서만 802.1Q 태그(TPID, TCI)가 추가되며, TCI 값(0x00a=10진수 10)을 통해 해당 프레임이 VLAN10에 속함을 확인하였다. MAC/IP 주소는 액세스·트렁크 구간에서 동일하게 유지되어, VLAN 태깅이 기존 프레임 정보를 훼손하지 않고 부가 정보만 추가하는 방식임을 검증하였다.

## 6. 정리

본 프로젝트를 통해 VLSM 기반 주소 설계, OSPF 멀티에어리어 및 이중 링크 Cost 설계, VLAN 분리 및 두 가지 Inter-VLAN Routing 방식(Router-on-a-Stick, SVI)의 비교 구현, ACL을 통한 접근 제어, 정적·동적 라우팅을 결합한 분할 라우팅까지 엔터프라이즈 네트워크 설계의 핵심 요소를 통합적으로 구현하고 검증하였다.

특히 캡처 분석을 통해 이론적으로만 학습했던 MAC/IP 주소의 역할 차이, VLAN 태깅 동작 원리, ACL의 실제 차단 메커니즘, OSPF의 자동 장애 복구 과정을 실증적으로 확인할 수 있었다.
